# Production Monitoring and SLOs

This document defines production monitoring for Invoice NER. It separates
service reliability, inference performance, and extraction quality so alerts are
actionable instead of noisy.

## Monitoring Goals

- Detect API, Triton, and monitoring failures within minutes.
- Track latency and errors under realistic invoice traffic.
- Measure extraction quality with offline labeled evals before deploy.
- Keep online eval and human-review sampling as a later phase.

## Service Level Objectives

Initial SLOs should be treated as release-candidate targets until a real
production baseline exists.

| Area | SLI | Initial SLO | Measurement Source | Alert Window |
| --- | --- | --- | --- | --- |
| API availability | successful `/predict` requests / total `/predict` requests | >= 99.5% | Prometheus `inference_requests_total` | 5m and 30m |
| API E2E latency | `/predict` p95 end-to-end latency | baseline first, then set target | Prometheus `inference_latency_seconds_bucket` | 5m |
| Model latency | p95 model-only latency | < 1.0s | API `model_inference_latency_seconds_bucket` after rebuild | 5m |
| Model tail latency | p99 model-only latency | < 2.0s | API `model_inference_latency_seconds_bucket` after rebuild | 5m |
| API health | `invoice-ner-app` scrape health | up | Prometheus `up{job="invoice-ner-app"}` | 1m |
| Triton health | `tritonserver` scrape health | up | Prometheus `up{job="tritonserver"}` | 1m |
| Extraction coverage | `Not Found` predictions / total predictions | < baseline + 10 percentage points | API metric to add | 30m |
| Fallback behavior | fallback requests / total predictions | within baseline band | Prometheus `fallback_total` | 30m |
| Offline quality gate | normalized exact match on labeled eval set | >= agreed release threshold | `scripts/eval_invoice_extraction.py` output | per release |

Quality SLOs need real baselines. Do not page on `not_found_rate` or fallback
rate until at least one representative production-like run establishes normal
ranges.

## Error Budget

For the initial API availability SLO of 99.5%, the monthly error budget is
approximately 0.5% of `/predict` requests. Burn rate should be evaluated over
short and long windows:

- Fast burn: page when `/predict` error rate exceeds 1% for 5 minutes.
- Slow burn: create a ticket when `/predict` error rate exceeds 0.5% for 30
  minutes.
- Quality burn: create a ticket when offline eval normalized exact match
  regresses by more than 2 percentage points from the previous release.

## Current Metrics

Already emitted by the API:

- `inference_requests_total{method,status}`
- `inference_errors_total{method}`
- `inference_latency_seconds`
- `model_inference_latency_seconds{backend,model_name}`
- `fallback_total`

Triton is also scraped on `tritonserver:8002` and currently emits model-serving
counters such as `nv_inference_request_duration_us`,
`nv_inference_queue_duration_us`, `nv_inference_compute_infer_duration_us`,
`nv_inference_request_success`, and `nv_inference_exec_count`. These support
moving-average model duration panels, not p95/p99 percentiles.

Already scraped:

- API `/metrics`
- Triton `/metrics`

Already visualized:

- Request rate
- P50/P95/P99 end-to-end latency
- P50/P95/P99 model-only latency
- Error rate
- Fallback rate
- Triton request, queue, compute, and GPU panels

## Metrics to Add Next

Add these before calling the stack production-ready:

- `prediction_not_found_total{method}`
- `prediction_valid_format_total{method}`
- `ocr_parse_errors_total`
- `image_validation_errors_total`
- `request_payload_bytes`
- `response_payload_bytes`
- `active_requests`
- `model_backend_ready{backend}`
- `extraction_method_total{method}`
- `invoice_words_count`
- `invoice_box_count`

Avoid high-cardinality labels such as invoice number, filename, vendor name,
customer name, raw OCR text, or request IDs. Put those in redacted logs or
traces instead.

## Alert Policy

Page-worthy:

- API Prometheus target down for 1 minute.
- Triton Prometheus target down for 1 minute.
- `/predict` error rate > 1% for 5 minutes.
- model-only p99 latency > 2 seconds for 5 minutes.
- Container restart loop.

Ticket-worthy:

- `not_found_rate` exceeds baseline by 10 percentage points for 30 minutes.
- Fallback rate exceeds baseline by 10 percentage points for 30 minutes.
- Offline eval normalized exact match regresses by more than 2 percentage
  points.

## Dashboard Layout

Grafana dashboards are generated by:

```bash
uv run python scripts/generate_grafana_dashboards.py
```

Open:

- Executive overview: `http://localhost:3000/d/invoice-ner-executive`
- API and infra: `http://localhost:3000/d/invoice-ner-api-infra`
- Model behavior: `http://localhost:3000/d/invoice-ner-model`
- Load test: `http://localhost:3000/d/invoice-ner-load-test`
- Golden signals: `http://localhost:3000/d/invoice-ner-golden`

Minimum production dashboard sections:

- Golden signals: request rate, error rate, p50/p95/p99 latency, saturation.
- Model behavior: extraction method mix, fallback rate, not-found rate,
  valid-format rate, model-only latency.
- Triton: model readiness, inference count, queue latency, compute latency,
  memory, and GPU utilization.
- Data shape: OCR word count, box count, image size distribution.
- Eval trend: latest offline eval score and regression from previous release.

## Offline Eval Gate

Run before merging or deploying model/extraction changes:

```bash
uv run python scripts/eval_invoice_extraction.py \
  --api-url http://localhost:7860 \
  --dataset data/train/qa_dataset.json \
  --image-root data/SROIE2019/train/img \
  --limit 100 \
  --output-dir monitoring/evals/release_candidate
```

Release gates should include:

- Normalized exact match.
- Mean edit distance.
- Valid-format rate.
- Not-found rate.
- Extraction method counts.
- Latency p50/p95.

## Failure Drills

Run these before production:

- Stop Triton and confirm API behavior plus alerting.
- Stop API and confirm Prometheus target-down alert.
- Break Prometheus config in a branch and confirm smoke test fails.
- Remove Grafana dashboard provisioning in a branch and confirm smoke test fails.
- Send malformed OCR/image requests and confirm error metrics increment.

## Incident Runbook

First checks during an incident:

1. Open Grafana `Invoice NER - Executive Overview`.
2. Check Prometheus targets at `http://localhost:9090/targets`.
3. Check container status:

   ```bash
   docker compose ps
   docker stats --no-stream invoice-ner-app triton-server prometheus grafana
   ```

4. Check logs:

   ```bash
   docker compose logs --tail=200 invoice-ner
   docker compose logs --tail=200 tritonserver
   docker compose logs --tail=200 prometheus
   ```

5. Run the smoke test:

   ```bash
   uv run python scripts/monitoring_smoke.py
   ```
